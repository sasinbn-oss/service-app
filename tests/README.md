# เทสต์

เทสต์ที่นี่ยิงไปที่ **backend ที่รันอยู่จริง** ไม่ใช่ unit test ที่ mock ทุกอย่าง
เพราะของที่เคยพังจริงในโปรเจกต์นี้คือเรื่องที่ unit test จับไม่ได้ — ลำดับขั้นของงาน
สิทธิ์ของแต่ละตำแหน่ง การเขียนทับข้อมูลข้ามรอบ และเวลาไปกลับฐานข้อมูล

**รันกับฐานข้อมูลสำหรับพัฒนาเท่านั้น** เทสต์เปิดใบงานจริง อัปโหลดไฟล์จริง
และแก้ภาค/ทีมของผู้ใช้ทดสอบ อย่าชี้ไปที่ฐานข้อมูลของจริงเด็ดขาด

## เตรียมก่อนรัน

ต้องมีสามอย่างรันอยู่: ฐานข้อมูล · ที่เก็บไฟล์จำลอง · backend

```bash
# 1) ที่เก็บไฟล์จำลอง (แทน Supabase Storage) — ค้างไว้อีกหน้าต่าง
node tests/mock-s3.js

# 2) backend ที่ชี้ไปที่ที่เก็บไฟล์จำลอง — ค้างไว้อีกหน้าต่าง
cd backend
STORAGE_ENDPOINT=http://localhost:9100 STORAGE_REGION=us-east-1 \
STORAGE_ACCESS_KEY_ID=dev STORAGE_SECRET_ACCESS_KEY=devsecret \
STORAGE_BUCKET=service-app npm run dev
```

**ครั้งแรกต้องเตรียมข้อมูลที่เทสต์ใช้ก่อน** รันซ้ำได้ ไม่ลบอะไรที่มีอยู่:

```bash
cd backend && npm run seed:test
```

สร้างให้: ผู้ใช้ `A001` (แอดมิน) `S001` (หัวหน้าภาค) `T001` (ช่าง) รหัสผ่าน `test1234`
· สาขา `C0001` `C0006` (บริษัท) `D0011` `D0012` (แฟรนไชส์ คนละฝั่งของเส้นประกัน 3 ปี)
· อะไหล่ `SP-BOARD` `SP-BELT`

แยกจาก `prisma db seed` เพราะคนละเรื่อง — อันนั้นคือข้อมูลตัวอย่างของระบบจริง
ส่วนอันนี้คือฉากที่เทสต์ต้องการ ถ้าปนกันระบบจริงจะมีบัญชีรหัสผ่านง่าย ๆ ติดไปด้วย
และสคริปต์จะปฏิเสธถ้า `DATABASE_URL` ชี้ไปที่ฐานข้อมูลบนคลาวด์

**ข้อควรระวังที่เสียเวลาไปหลายรอบแล้ว** — พลาดทุกข้อนี้ทำให้เทสต์ "ผ่าน"
ทั้งที่แอปไม่ได้ทำงาน:

- **หน้ารายการยังค้างอยู่ใน DOM ข้างหลังหน้ารายละเอียด** หาข้อความแบบเจาะจงใบ
  ไม่ใช่เอาอันแรกที่เจอ
- **ใบงานกับฟอร์มเปิดใบงานเป็นหน้าต่างลอย หน้าข้างหลังยังมองเห็นและอยู่ก่อนใน DOM**
  ข้อความเดียวกัน (ชื่อสาขา เลขใบงาน) มีทั้งข้างหน้าและข้างหลัง — เลือกตัวที่อยู่บนสุด
  ด้วย `document.elementFromPoint` (ดู `topmost` ใน `capacity-web-test.js`) ห้ามใช้ click
  สำรองแบบ `el.evaluate(n => n.click())` กับตัวแรกที่เจอ เพราะมันกดทะลุฉากมืดไปที่รายการข้างหลังได้
- **แถบขั้นตอนไม่มีหัวข้อ "ขั้นตอนงาน" แล้ว** หาจาก `aria-label="ขั้นตอนงาน"` แทน
- **แถบขั้นตอนงานมีชื่อทุกขั้นอยู่แล้ว** เช็คสถานะต้องอ่านจากป้ายบนหัวใบงาน
  ไม่ใช่ค้นทั้งหน้า ไม่งั้นเจอ "รอหัวหน้าภาคจ่ายงาน" ตลอดไม่ว่าสถานะจริงเป็นอะไร
- **แท็บอื่นยังถูกวาดค้างอยู่ข้างหลัง** ปุ่ม ☰ กับชื่อหน้ามีหลายตัวในหน้า `.first()` ได้ตัวที่ถูกบัง
  — ใช้ `topmost` เสมอ และจอกว้างเมนูข้างค้างอยู่แล้ว ไม่ต้องกด ☰
- **บันทึกสำเร็จที่มีหัวข้อ + ข้อความ ขึ้นเป็นกล่องที่ต้องกด "ตกลง"** (ไม่ใช่ toast) กล่องนี้บังทั้งหน้า
  ไม่กดปิด การกดถัดไปจะไม่ไปถึงปุ่ม
- **Expo ที่รันด้วย `CI=1` ไม่เห็นไฟล์ใหม่** เพิ่มหน้าใหม่แล้วต้องสั่ง expo ใหม่ ไม่งั้นทั้งแอปขาว
  (ไม่มีช่องรหัสพนักงานให้กรอก)
- **ช่องวันที่/เวลา/ตัวเลือกเป็นกล่องลอยวาดท้าย body** — ปุ่มในกล่อง (เช่น "เดือนถัดไป") ชื่อซ้ำกับปุ่มบนหน้า
  ได้ ใช้ `.last()` · ช่องวันที่พิมพ์ไม่ได้แล้ว ต้องกดช่องแล้วกดวันจาก `aria-label` แบบ "อ. 20 ต.ค. 2569"
- **ปุ่มส่งฟอร์มของโมดัลชื่อ "ยืนยัน"** ส่วน "บันทึกเพิ่มเติม" เป็นหัวข้อช่องหมายเหตุ
  และหัวหน้าจอ "เปิดใบงานใหม่" มีคำว่า "เปิดใบงาน" อยู่ข้างใน — ใช้ `exact: true`
- **กล่องยืนยันบนเว็บเป็นของแอปเอง ไม่ใช่ `window.confirm`** อ่านข้อความจาก DOM
  แล้วกดปุ่มในกล่องด้วยข้อความ (เช่น "ลบถาวร") — `page.on("dialog")` จะไม่มีอะไรเข้ามา
  ส่วนแจ้งผลสำเร็จ/ผิดพลาดเป็น toast ด้านบนที่หายเองใน 3.5 / 6 วินาที
- **`filechooser.setFiles()` กับไฟล์ที่ path มีภาษาไทยหรือช่องว่าง** Chromium ยิง `cancel`
  แทน `change` ฟอร์มไม่ได้ไฟล์และไม่มี error อะไรเลย — ดูเหมือนแอปพัง ทั้งที่ผู้ใช้จริงเลือกได้ปกติ
  ก๊อปไฟล์ทดสอบเป็นชื่ออังกฤษก่อนส่งเข้า chooser เสมอ
- **ส่ง SQL ให้ `psql` ทาง stdin ไม่ใช่ `-c "…"` ผ่าน shell** รหัสผ่านที่แฮชแล้วขึ้นต้นด้วย `$2b$10$`
  shell กิน `$…` ไปเงียบ ๆ ผู้ใช้ทดสอบที่สร้างเลยล็อกอินไม่ได้ (ดู `sql` ใน `claim-web-test.js`)
- **ยืนยันผลที่ฐานข้อมูลด้วย** อย่าเชื่อข้อความบนหน้าจออย่างเดียว

## เพิ่มเทสต์ใหม่

ลอกชุดที่ใกล้เคียงที่สุดมาเป็นแบบ ทุกชุดใช้โครงเดียวกัน: `login()` เอา token,
`pass`/`fail` รายงานผล, `J` แกะ JSON ด้วย node

**ตั้งภาคของหัวหน้าภาคให้ตรงกับสาขาที่ทดสอบตั้งแต่ต้นไฟล์** ก่อนเรียก API ใด ๆ
ไม่งั้นผลจะขึ้นกับว่าชุดก่อนหน้าทิ้งอะไรไว้ และรันเดี่ยว ๆ จะไม่ผ่าน

**ลบข้อมูลที่สร้างไว้เมื่อทำงานเสร็จ** ชุดพวกนี้ไม่ได้ลบให้เอง — ตั้งใจให้ดูผลย้อนหลังได้
ลบด้วย Prisma เมื่อไม่ต้องการแล้ว
