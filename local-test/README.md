# ระบบทดสอบในคอม (ออฟไลน์)

สำเนาของระบบ OTTERI ทั้งชุดที่รันในคอมเครื่องเดียว: ฐานข้อมูล · เซิร์ฟเวอร์ · หน้าเว็บ · ที่เก็บรูป
**แยกจากระบบจริงทั้งหมด** ทีมลองกดอะไรก็ได้ ไม่กระทบใบงานจริง ไม่มีอะไรส่งออกไปถึงลูกค้าหรือพนักงาน

ทุกหน้ามีแถบสีส้ม **"ระบบทดสอบ"** ด้านบน — ถ้าไม่เห็นแถบนี้ แปลว่ากำลังอยู่ในระบบจริง

---

## ติดตั้งครั้งแรก (ทำครั้งเดียว · ต้องมีเน็ต)

1. **ติดตั้ง Docker Desktop** — https://www.docker.com/products/docker-desktop/ (ฟรี มีทั้ง Windows และ Mac)
   - Windows: ถ้าถามให้ติดตั้ง WSL 2 ให้กดตกลง แล้วรีสตาร์ทเครื่อง
   - เปิด Docker Desktop ค้างไว้ (ไอคอนวาฬมุมจอต้องขึ้นว่า running)
2. **เอาโค้ดลงเครื่อง** — หน้า GitHub ของโปรเจกต์ → ปุ่ม **Code** → **Download ZIP** → แตกไฟล์
   (หรือใช้ `git clone` ถ้าเคยใช้ git)
3. **เปิดหน้าต่างคำสั่ง** ที่โฟลเดอร์ `local-test`
   - Windows: เปิดโฟลเดอร์ `local-test` → คลิกที่ช่องที่อยู่ด้านบน พิมพ์ `powershell` กด Enter
   - Mac: คลิกขวาที่โฟลเดอร์ `local-test` → **New Terminal at Folder**
4. **สั่งเปิดระบบ**

   ```
   docker compose up -d --build
   ```

   ครั้งแรกใช้เวลาราว 10–15 นาที (ดาวน์โหลดและสร้างระบบ) ครั้งต่อไปไม่กี่วินาที
5. รอสัก 1–2 นาทีให้ใส่ข้อมูลตัวอย่างเสร็จ แล้วเปิดเบราว์เซอร์ไปที่ **http://localhost:8080**

หลังจากนี้ **ถอดเน็ตได้** — ระบบทำงานในคอมทั้งหมด

## บัญชีสำหรับทดสอบ (รหัสผ่าน `test1234` ทุกบัญชี)

| รหัสพนักงาน | ตำแหน่ง | ชื่อในระบบ |
|---|---|---|
| `A001` | แอดมิน | อรวรรณ |
| `S001` | หัวหน้าภาค (ภาคกลาง-ตะวันตก) | วีระ |
| `T001` | ช่าง (ทีมกรุงเทพ) | สมชาย ใจดี |
| `SP01` | Admin Spare Part | วิภา |
| `SA01` | Super Admin | สมศักดิ์ |

มีใบงานตัวอย่างครบทุกขั้นให้ลองกดต่อได้ทันที: ระบุอะไหล่ · ตรวจหน้างาน · เช็คอะไหล่ · เสนอราคา · รับเงิน ·
อะไหล่หมด · เบิก/โอนข้ามคลัง · จ่ายงาน · คอนเฟิร์มลูกค้า · ปล่อยงาน · ช่างเข้างาน · รอตรวจเคลม · ปิดแล้ว

## ให้ทีมเข้าจากเครื่องอื่น (วง Wi-Fi เดียวกัน)

1. หา IP ของคอมที่เปิดระบบ
   - Windows: พิมพ์ `ipconfig` ในหน้าต่างคำสั่ง ดูบรรทัด **IPv4 Address** (เช่น `192.168.1.25`)
   - Mac: System Settings → Wi-Fi → Details → **IP address**
2. เครื่องอื่นเปิด **http://192.168.1.25:8080** (เปลี่ยนเป็น IP ที่ได้)
3. ถ้าเปิดไม่ได้: Windows อาจถาม Firewall ตอนเปิดครั้งแรก ให้กด **Allow** (Private network)

## ข้อจำกัด

- **GPS (รายงานตัวเข้าสาขา) และกล้อง (ถ่ายป้ายรุ่น) ใช้ได้เฉพาะบนคอมที่เปิดระบบ** (`localhost`)
  — มือถือที่เข้าผ่าน `http://IP` เบราว์เซอร์จะบล็อกสองอย่างนี้ (กฎความปลอดภัยของเบราว์เซอร์ ไม่ใช่ของระบบ)
  ส่วนการ **เลือกรูปจากเครื่อง** ยังใช้ได้ทุกเครื่อง
- ไม่มีเน็ต: ฟอนต์จะเปลี่ยนเป็นฟอนต์ของเครื่อง (หน้าตาต่างเล็กน้อย) · วางลิงก์ Google Maps ในหน้าสาขาไม่ได้
- คอมต้องเปิดค้างไว้ระหว่างที่ทีมทดสอบ

## คัดลอกข้อมูลจริงมาทดสอบ (ไม่บังคับ)

ใช้แทนข้อมูลตัวอย่างได้ เมื่ออยากลองกับสาขา/ใบงาน/รายชื่อจริง

1. ระบบจริง → เข้าด้วย Super Admin → **สำรองข้อมูล** → กด **ไฟล์กู้คืน** ได้ไฟล์ `OTTERI-backup-....json.gz`
2. วางไฟล์ไว้ในโฟลเดอร์ `local-test/backup/`
3. ถ้าเคยเปิดระบบทดสอบมาก่อน ต้องล้างของเดิมก่อน (ข้อมูลกู้ได้เฉพาะลงฐานข้อมูลว่าง): `docker compose down -v`
4. `docker compose up -d --build` → ระบบกู้ข้อมูลจากไฟล์ให้เอง ใช้**รหัสผ่านเดิม**ของแต่ละคน

ข้อควรรู้:
- **รูปหน้างานจะไม่ขึ้น** — รูปอยู่ในที่เก็บไฟล์ของระบบจริง ไม่ได้อยู่ในไฟล์สำรอง และ**ระบบทดสอบต้องไม่ต่อกับที่เก็บไฟล์จริง**
  (ทีมลบใบงานในระบบทดสอบ = ลบรูปจริง) รูปที่อัปโหลดใหม่ระหว่างทดสอบใช้ได้ปกติ
- ⛔ **ไฟล์สำรองคือข้อมูลทั้งบริษัท** (รายชื่อ เบอร์โทร สาขาทั้งหมด) — ห้ามส่งต่อ · ลบทิ้งเมื่อเลิกใช้ ·
  `.gitignore` กันไม่ให้เข้า git แล้ว
- คอมที่เปิดระบบเก็บข้อมูลจริงไว้ในเครื่อง — ใช้คอมของบริษัท

## คำสั่งที่ใช้บ่อย (พิมพ์ในโฟลเดอร์ `local-test`)

| ต้องการ | คำสั่ง |
|---|---|
| ปิดระบบ (ข้อมูลยังอยู่) | `docker compose stop` |
| เปิดอีกครั้ง | `docker compose up -d` |
| **ล้างทุกอย่าง เริ่มใหม่** (ข้อมูลตัวอย่างชุดใหม่) | `docker compose down -v` แล้ว `docker compose up -d --build` |
| อัปเดตเป็นโค้ดล่าสุด | ดาวน์โหลด ZIP ใหม่ (หรือ `git pull`) แล้ว `docker compose up -d --build` — ข้อมูลเดิมยังอยู่ |
| ดูว่าเกิดอะไรขึ้น (เปิดไม่ขึ้น) | `docker compose logs backend` |

## เปิดไม่ขึ้น — ไล่ตามนี้

| อาการ | แก้ |
|---|---|
| `port is already allocated` | โปรแกรมอื่นใช้พอร์ต 8080 อยู่ — แก้ `"8080:80"` ใน `docker-compose.yml` เป็น `"8090:80"` แล้วเปิด `http://localhost:8090` |
| หน้าเว็บขึ้นแต่เข้าสู่ระบบไม่ได้ / "เชื่อมต่อเซิร์ฟเวอร์ไม่ได้" | เซิร์ฟเวอร์ยังเตรียมข้อมูลครั้งแรกไม่เสร็จ รอ 1–2 นาที · ยังไม่ได้ดู `docker compose logs backend` บรรทัดท้าย ๆ |
| ไม่มีใบงานตัวอย่าง | `docker compose logs demo` · สั่งใส่ใหม่ได้ด้วย `docker compose up demo` |
| `Cannot connect to the Docker daemon` | ยังไม่ได้เปิด Docker Desktop |

## สำหรับนักพัฒนา — ทำงานอย่างไร

| ส่วน | อยู่ที่ | หมายเหตุ |
|---|---|---|
| `web` | `web.Dockerfile` + `nginx.conf` | build เว็บแบบเดียวกับระบบจริง ด้วย `EXPO_PUBLIC_API_URL=same-origin` (เรียก API ที่อยู่เดียวกับหน้าเว็บ) และ `EXPO_PUBLIC_APP_ENV=test` (แถบส้ม) · nginx ส่ง `/api` `/health` ให้ backend และ `/service-app/` (ไฟล์) ให้ storage |
| `backend` | `backend.Dockerfile` + `backend-start.sh` | โค้ดชุดเดียวกับระบบจริง · migrate → ครั้งแรก: กู้จาก `backup/` หรือใส่ข้อมูลตัวอย่าง (`prisma/seed.ts` + `seed-test-fixtures.ts` + `seed-extra.js`) · หยุดทันทีถ้า `DATABASE_URL` ไม่ใช่ `db:5432` · `STORAGE_BROWSER_RELATIVE=1` ให้ลิงก์ไฟล์เป็น `/service-app/...` |
| `storage` | `file-store.js` | ที่เก็บไฟล์แบบ S3 ขนาดเล็ก เก็บลง volume `files` (MinIO เลิกลง Docker Hub แล้ว) — ไม่ตรวจลายเซ็นลิงก์ |
| `demo` | `demo-orders.js` + `demo-files/` | สร้างใบงานตัวอย่างผ่าน API ครั้งเดียว — ข้ามเมื่อมีใบงานแล้วหรือกู้จากไฟล์สำรอง |
| `db` | `postgres:16-alpine` | volume `db-data` |

ทุก service อยู่ใน docker network ของตัวเอง เปิดออกนอกเครื่องแค่พอร์ต 8080 (หน้าเว็บ)
